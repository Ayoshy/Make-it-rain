1. CE QUE JE VEUX ACCOMPLIR

Battlestation est mon bureau personnel Windows, en .NET/WPF, avec un dock LoL déjà fonctionnel pour la télémétrie classique.

Je veux pouvoir détecter automatiquement, pendant une partie ARAM Mayhem :
- les trois améliorations actuellement proposées ;
- les changements de propositions après chaque reroll ;
- idéalement l’amélioration finalement choisie ;
- les données assez rapidement pour les exploiter dans Battlestation pendant la phase de choix.

La priorité est de démontrer une lecture fiable. L’interface finale, les recommandations et une éventuelle source de statistiques viennent après.

Le critère de réussite est concret : les trois noms/identifiants récupérés correspondent aux cartes visibles, puis se mettent correctement à jour après un vrai reroll. Un catalogue statique, les améliorations déjà choisies ou un historique de fin de partie ne suffisent pas.

Le fonctionnement doit être autonome pendant la partie. Je ne veux pas devoir prévenir l’agent à chaque choix ou reroll, et les interruptions de conversation ne doivent pas arrêter la collecte.

2. MES PRÉFÉRENCES ET DÉCISIONS

- Application personnelle sur mon PC, pas un produit public.

- J’ai finalement autorisé la piste Overwolf, avec préférence pour une variante autonome, comme CurseForge sans client Overwolf complet.

- Évite aussi l’erreur inverse : une possibilité théorique ou un exemple GitHub ne constitue pas une solution validée.
- N’annonce pas de risque de ban nul pour une approche non vérifiée.

7. OVERWOLF : POSSIBILITÉ DOCUMENTÉE, BLOCAGE RÉEL OBSERVÉ

Overwolf documente une fonctionnalité GEP « augments » pour ARAM Mayhem :
- trois propositions, avec augment_1 / augment_2 / augment_3 ;
- picked_augment pour le choix effectué.

Cela correspond à notre besoin sur le papier. Nous n’avons reçu aucun de ces événements en pratique.

Deux variantes existent :
- Overwolf Native, avec le client complet ;
- Overwolf Electron, autonome, sans client Native obligatoire.

La variante autonome reste fondée sur des composants propriétaires Overwolf. Elle ne garantit pas l’absence de télémétrie.

Politiques consultées :
- approbation/autorisation demandée pour les applications ;
- applications privées et passerelles vers un autre service explicitement concernées par leur refus actuel d’approbation ;
- ne pas confondre cette politique avec un résultat de test technique.
